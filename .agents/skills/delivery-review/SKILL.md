# Delivery Review

1. Reconcile approved discovery scope, accepted changes, feature map, tasks, and actual implementation.
2. Confirm all required task and pre-delivery gates passed.
3. Assemble evidence for functional behavior, authorization, data integrity, accessibility, performance, security, compatibility, and operations according to project risk.
4. Document deployment steps, configuration, secrets ownership, migration/backfill, observability, rollback, support ownership, and known limitations.
5. Create a stakeholder acceptance checklist tied to observable outcomes, not implementation details.
6. Distinguish release blockers from accepted known issues with owners and due dates.
7. Record release approval and evidence paths.
8. Run a harness retrospective: identify reusable improvements, but promote a lesson into reusable skills only when it generalizes beyond this project.
9. Use `assets/delivery-checklist-template.md`.

Do not declare delivery complete solely because all task files say `done`.
